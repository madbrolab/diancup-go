## 致用户

2025 年初，试过不少 Docker 更新工具后，始终没找到完全符合自己习惯的，于是决定做一个自用项目，这便是 DIANCUP 的起点。

从最初的容器更新，到宿主机监控、多机联动的 Docker 面板，再到如今的导航页，期间经历了多次前后端重构：Python 换 Go，原生 JS 换 Vue，功能越堆越多，界面由丑变美、又由美变丑，名字和仓库地址也换过多次，一路折腾到了今天。

**权限与风险请务必了解：** 本项目从自用出发，按宿主机最高管理权限设计。对于常见的 root 权限 Docker 环境，即使不直接授予宿主机目录访问权限，只要能通过 `docker.sock` 完整管理 Docker，就能创建临时容器、挂载宿主机目录，进而读写主机文件，实质上具有 root 级控制能力。其他拥有相同 Docker 权限的项目也存在这一风险。**介意此类权限或无法承担风险的用户，请勿使用。** 作者不保证项目不存在漏洞，对因使用本项目造成的主机、服务器或 VPS 文件损坏、数据丢失、资料泄露等损失不承担责任。

感谢从 DPanel 更名为 DIANCUP，一路陪伴重构、堆料、反馈问题和提供建议的小伙伴。这个原本只打算自己用的小工具，能走到今天，离不开你们的支持。

## 关于本仓库

DIANCUP 将个人导航、Docker 管理和主机运维集中在一个 Web 界面中，适合家庭 NAS、自建服务及多台 Linux 设备的日常管理。本仓库提供使用说明、在线演示、浏览器插件安装包和[应用模板商店](store/README.md)。

- 导航首页：`/`；管理后台：`/dashboard`
- 首次部署：[安装与启动](#docker-compose-部署) → [获取初始验证码并设置密码](#首次获取验证码与设置密码)

### 导航与移动端

导航采用 Liquid Glass 风格，电脑和手机可分别设置卡片布局与背景。登录后可拖动卡片、调整尺寸、编辑分类或设置私有入口；手机支持长按菜单，也可将两个常用入口固定到手机底栏。支持 PWA 安装，工作台、文件管理和 SSH 页面也适配移动端。

### 容器、项目与文件

容器详情可查看端口、挂载、环境变量、网络和标签，并直接打开日志、控制台及容器文件。镜像更新检查逐项显示结果、进度与耗时，更新时沿用原有配置及数据挂载。现有容器可生成 Compose，新项目可先核对配置、环境变量和目标设备，再跟踪部署任务直至完成。

宿主机文件管理统一显示真实绝对路径，可直接复制到部署配置中使用。文件操作在目标设备执行；容器文件入口用于访问容器内部路径，具体可用操作取决于目标设备和文件权限。

### 模板部署与多机协作

模板商店面向个人与家庭 NAS 应用，支持工具、影音、下载、存储、游戏等用途分类。安装时可选择目标设备、项目目录、端口及共享资料目录，填写必要变量并查看建议修改项。模板源在「公共配置」中管理；同步失败保留已同步的索引，已有项目和安装记录仍可管理。

多机管理支持探针与异地主机主动回连，也可在 SSH 工作台直接连接服务器。每台设备可维护自己的部署目录、挂载范围、资料库、用户 ID 和端口范围；批量任务保留各设备的执行结果，便于集中检查与更新服务。

## STUN 协同访问

您可以给导航页配置一个 Cloudflare Tunnel 隧道地址，例如 `https://nav.example.com`，再将它填入导航设置的“STUN 协同访问地址”，并把网络模式设为“自动识别”。

自动识别先判断内外网。通过该地址打开导航页，内网直连或配置的 DIANCUP 内网地址探测成功时，点击卡片使用内网地址；只有内网不可达且入口匹配协同域名时，才识别为“协同 · STUN”，使用卡片配置的 STUN 地址和 Lucky 同步的动态端口。普通外网入口使用公网地址。

导航页通过 CF 隧道加载，外网访问卡片可通过 STUN 直连，减少服务访问经过隧道带来的速度影响，也无需记住变化的 STUN 端口。

例如，卡片内网地址为 `http://192.168.2.2:8096/web`，公网地址为 `https://media.example.com`，STUN 地址为 `http://direct.example.com/web`，Lucky 同步端口为 `45678`。通过同一个隧道域名打开导航页，内网探测成功时点击卡片打开 `http://192.168.2.2:8096/web`；外网协同模式下打开 `http://direct.example.com:45678/web`。未配置卡片 STUN 地址或没有有效端口时，回退 `https://media.example.com`。公网地址也未配置时才使用内网地址。

协同地址识别当前导航页域名（含其子域名），可填写域名或完整 URL；它和卡片的 STUN 跳转地址分别配置。手动选择内网、公网或 STUN 可覆盖自动识别；需要自动切换时请先切回“自动识别”。HTTPS 导航页探测 HTTP 内网地址可能被浏览器拦截，此时可配置可探测的 HTTPS 内网地址或手动切换内网。

## Docker Compose 部署

先安装 Docker Engine 和 Docker Compose 插件，再创建 `compose.yaml`：

```yaml
services:
  diancup:
    image: madbrolab/diancup:latest
    container_name: diancup
    privileged: true
    restart: unless-stopped
    ports:
      - "9520:9520"
    volumes:
      - ./config:/config # 保存数据库与配置，也可改为宿主机绝对路径
      - /:/host # 主机管理使用，保持此挂载
    environment:
      TZ: Asia/Shanghai
      WEB_PORT: "9520"
      DOCKER_DIR: /mnt/cache/docker # 必须改为宿主机实际的 Compose 项目目录
```

将 `DOCKER_DIR` 改为宿主机实际的 Compose 项目目录，然后启动：

```bash
docker compose pull
docker compose up -d
```

导航首页为 `http://服务器地址:9520/`，管理后台为 `http://服务器地址:9520/dashboard`。如需调整端口，请同时核对 `ports` 映射和 `WEB_PORT`。

### 首次获取验证码与设置密码

**新安装没有通用默认密码。** 首次启动会在配置目录生成 `setup-token` 文件，内容是用于设置密码的一次性验证码。

1. 在服务器终端进入 `compose.yaml` 所在目录，读取验证码：

   ```bash
   docker compose exec diancup cat /config/setup-token
   ```

   使用上述示例的容器名时，也可在服务器任意目录执行：

   ```bash
   docker exec diancup cat /config/setup-token
   ```

   如果直接读取宿主机文件，示例中的位置为 Compose 项目目录下的 `./config/setup-token`；改过配置挂载时使用实际目录。文件权限为 `0600`，需要有权限的账号读取，例如在项目目录执行 `sudo cat ./config/setup-token`。

2. 打开 `http://服务器地址:9520/dashboard`，在首次设置页面的「初始验证码」中粘贴文件内容，再填写管理密码和确认密码。密码至少 8 位，包含字母和数字，并避免常见弱密码。
3. 设置成功后，使用自己刚设置的管理密码登录。一次性验证码失效，`setup-token` 文件会自动删除；导航管理与后台使用同一管理密码。

已有实例升级后沿用原密码，不需要重新获取验证码。启动日志只提示验证码文件位置，不会打印验证码或管理密码。若部署时自行配置了至少 32 字符的 `DIANCUP_SETUP_TOKEN` 环境变量，则使用该值作为初始验证码，应用不会另外生成文件。

### 访问与数据保留

登录限流默认使用真实连接地址。部署在反向代理后时，可通过 `TRUSTED_PROXIES` 指定可信代理 IP 或 CIDR（逗号分隔），并让代理覆盖转发地址、保留原始 Host；不要将不可信客户端列为代理。密码或两步验证变更后其他会话失效，退出登录的会话不能继续使用。

SSH 工作台首次连接记录服务器指纹，后续变化会拒绝连接；确认服务器确已更换密钥后，管理员可向 `/api/ssh/clear-keys` 提交 `{ "server_id": "已保存的服务器ID" }` 清除该服务器指纹，再重新连接。首次连接仍需通过可信网络确认服务器身份。

`/config` 保存数据库及配置，更新时保留此目录及原有挂载。`/:/host` 和特权模式用于主机管理功能；请将管理入口放在可信网络中，外部访问建议使用 HTTPS 反向代理。

更新镜像时再次执行上述 `pull` 与 `up -d`；不要删除配置目录。Docker 会自动选择对应的 CPU 架构。

「设置 → 系统」可导入导出配置数据库（SQLite）。数据库备份不包含其他应用的数据、上传资源或 AI 记忆文件；迁移完整实例时，应一并保留 `/config` 中的相关文件及自行配置的外部记忆目录和密钥。

### 镜像检查与更新方式

容器列表会区分本地镜像、固定摘要和版本标签。本地镜像缺少仓库摘要时跳过检查；`@sha256:` 固定摘要也跳过。`1.2.3`、`latest`、`stable` 等标签只比较当前标签的内容，不会自动切换到其他版本或 `latest`。版本标签仍可能被仓库重新推送。容器与仪表板的“更多”菜单可按容器跳过或恢复更新检查，设置保存在 `/config`；带 `com.docker.updater.exclude` 排除标签的容器继续显示，但需修改部署标签才能恢复检查。

容器更新和 DIANCUP 自更新通过 Docker Engine API 执行，不调用宿主机的 Compose、Python 或更新脚本。需允许应用访问 Docker socket；绑定目录和数据卷仍由宿主 Docker 管理。镜像拉取由 Docker 守护进程执行，其网络和代理配置仍需可用。自更新通过临时更新器接管，更新过程保留原配置、挂载、资源限制、网络及运行/停止状态，替换失败时尝试恢复原容器。私有仓库可在应用容器内提供 `DOCKER_AUTH_CONFIG` 或只读 Docker `config.json`，不执行宿主凭据助手。

## 浏览器插件

插件支持将当前网页或右键选择的链接添加到导航分类，并可选择是否将 DIANCUP 用作新标签页。

### Chrome / Edge 安装

1. 下载并解压 ZIP。
2. 打开 `chrome://extensions/` 或 `edge://extensions/`。
3. 开启开发者模式，选择「加载已解压的扩展程序」，选中解压目录。
4. 打开插件设置，填写 DIANCUP 的 HTTP/HTTPS 地址与专用插件 API Key。
5. 测试连接并保存，然后从插件弹窗或网页右键菜单添加入口。

专用 API Key 在登录后的导航设置中生成；它不是管理密码。重新生成 Key 会使旧 Key 失效。浏览器对 CRX 的安装限制因渠道或策略而异，若无法安装请使用 ZIP 方式。

插件安装包只包含运行资源，不包含主工程源码；签名私钥不会公开。

### 使用说明

首次测试或保存时，浏览器会请求访问填写的 DIANCUP 服务器；API Key 和服务器地址保存在本机。添加入口时，内网、外网或 STUN 地址至少填写一个，并可选择公开或私有状态。升级插件或修改服务器地址后，重新打开插件设置，测试并保存一次以授予服务器访问权限。

## Lucky STUN 接入

DIANCUP 消费 Lucky 已获取的映射结果，自动更新导航卡片的动态端口。请先按 [Lucky 官方 STUN 说明](https://www.lucky666.cn/docs/modules/stun/) 配置穿透规则。

1. 在卡片中填写 **STUN 地址**，例如 `https://media.example.com:12345/web/`；在导航布局设置中填写 **STUN 协同访问地址**。自动模式先探测内网，仅在内网不可达且当前入口匹配协同域名时使用 STUN；也可从顶部菜单手动选择网络模式。
2. 添加 Lucky 组件，填写服务器地址和 OpenToken。STUN 规则默认名为 `diancup`，可在卡片配置中改为实际规则名。无回调时也会按需查询端口。
3. 在导航设置的「布局 → Lucky STUN 接入与端口同步」中生成专用回调密钥。它与插件 API Key、管理密码独立。
4. 在 **此导航服务对应的 Lucky 穿透规则** 中设置 Webhook，使用 Lucky 可访问的 DIANCUP 内网地址：

   ```text
   POST http://DIANCUP内网地址:9520/api/navigation/lucky/webhook
   Content-Type: application/json
   X-STUN-Token: 导航设置生成的回调密钥
   ```

   ```json
   {"msgtype":"text","text":{"content":"#{ip}，#{port}"}}
   ```

   IP 和端口变量请使用 Lucky 当前版本面板提供的变量插入功能。也支持 `{"ip":"实际IP","port":"实际端口"}`；不支持自定义请求头时可在地址后添加 `?token=回调密钥`。

回调收到有效地址后即保存；端口变化会反映到访问链接，保留卡片配置的域名、协议和路径。IPv4 与带方括号的 IPv6 地址均可解析。导航处于 STUN 模式时约每 10 秒读取一次状态，其他模式按需降低频率；API 查询会校正已有缓存。回调请走稳定的内网地址，避免经由正在变化的 STUN 入口。

该机制使用一个共享穿透端口。多个独立映射规则不要共用此回调；卡片应指向同一 Lucky 反向代理入口或保留自己的固定地址。

## AI 助手与系统代理

在工作台设置中配置自己的模型接口并启用需要的工具权限。网页与 Telegram 均可按自然语言查询与管理容器、Compose、文件、主机、模板商店和导航书签；部署等后台操作会跟踪任务结果后再继续处理。

Telegram 通知配置保存后会自动注册命令。在 AI 设置中打开 Telegram 接入，白名单用户可使用：

| 命令 | 用途 |
| --- | --- |
| `/ai` | 开启或关闭当前用户的连续管理对话，普通通知独立生效 |
| `/ai 任务内容` | 单次管理任务 |
| `/ai_provider`、`/ai_model` | 查看按钮列表；后接名称或 ID 可直接切换，`default` 恢复默认 |
| `/stop`、`/clear` | 停止任务、清空上下文；历史记录和长期记忆保留 |
| `/ai_status`、`/ai_help` | 当前配置与命令说明 |

这些会话操作也可用自然语言要求 AI 执行。模型／提供商切换保留文字历史，下一轮使用新配置。Telegram 使用原生富文本显示表格、列表、引用和代码块，旧接口自动回退；执行过程在同一条进度消息中更新，最终回答独立发送。

记忆按实例共享给已授权的管理会话：`MY.MD` 仅保存简短偏好，设备、项目、长期约定和凭据保存在 `LONG_TERM.MD.enc`，按需检索相关片段。解密内容仅用于当前任务，任务记录和后续会话历史会脱敏。可直接说“记住这条部署约定”或“查询之前保存的 NAS 配置”。

默认记忆目录位于配置数据目录下的 `assistant/memory`，与数据库挂载一同保留；`DIANCUP_AI_MEMORY_DIR` 可指定目录。加密使用 AES-256-GCM，自动生成权限为 0600 的 `ai-memory.key`，也可通过 `DIANCUP_AI_MEMORY_KEY`（32 字节的 `base64:`／`hex:`）或外部 `DIANCUP_AI_MEMORY_KEY_FILE` 提供。恢复加密记忆须同时保留对应密钥；旧 `LONG_TERM.MD` 仅在成功加密后移除明文。密钥和记忆文件不得加入代码仓库或镜像。

- **精确查询**：容器列表与详情、镜像、项目、主机、进程、端口、网络、卷、文件和任务；可筛选并限制返回数量。其他能力通过实际管理 API 目录查询参数。
- **阅读与安装**：给出 GitHub 仓库地址、目标设备和绝对安装目录，助手先读取 README 和部署文件，再调用原生项目部署功能。创建全新项目不会覆盖现有目录；异步部署需等待任务结束后才报告结果。
- **远程设备**：先在 SSH 工作台保存服务器及连接凭据。AI 通过服务器目录选择准确设备并执行命令；SSH 设备无需安装探针，SSH 与探针目标保持独立。
- **联网范围**：可搜索、读取 HTTP(S) 正文、链接和仓库文件，长文支持分页。网页读取不执行页面 JavaScript；需要浏览器登录或动态渲染的内容可能无法获取。
- **模板商店**：只读取公共配置中已启用的 GitHub 仓库，不包含内置模板或离线样例。进入后直接显示卡片，上方按工具、影音、游戏、网站、下载、存储、网络、监控、开发、数据库、AI 和其他用途分类，显示分类数量，可配合关键词搜索。清空或停用来源后显示配置入口，已有项目和安装记录保留。
- **系统代理**：在「设置 → 代理设置」填写 HTTP 代理主机、端口，选择「全部公网地址」或「仅代理列表中的地址」。列表默认包含 GitHub、Docker、Telegram 及常用模型和搜索服务，旧配置首次补入，保留自定义规则，后续可自行增删或清空并保存。每行可填域名、IP、CIDR 或 HTTP(S) 地址；域名包含子域名，可指定端口，完整 URL 按主机和端口匹配。直连列表优先，本地及私有 IP 默认直连，显式代理规则可覆盖该默认行为。

模型请求、模型发现、搜索、网页读取、镜像检查和系统 HTTP 请求遵循上述代理规则。SSH 和 TCP 检查保持直连；Docker 镜像拉取由 Docker 守护进程执行，其代理需要在 Docker 自身配置。HTTP 代理配置不会自动修改其他设备或 Docker 守护进程的网络设置。

## 部署计划与设备管理

“Compose 项目 → 部署项目与任务”提供新项目部署入口。填写项目名称、宿主机真实绝对目录、完整 Compose 与可选的 `.env`，先检查部署计划，再执行部署。预检包括原生 Compose 配置解析、必填变量与引用文件、Docker 架构、磁盘、端口、外部网络、挂载边界和设备路径。新项目引用的 ENV、配置与构建文件须随部署提供，不读取项目外部文件或 DIANCUP 自身的私有环境。

部署内容和目标设备共同确定任务身份，重复提交返回原任务；配置变化后需重新预检。任务保存阶段和结果，刷新页面后可继续查询，也可停止执行。容器启动后继续检查稳定性、健康状态及已发布的 TCP 端口；一次性初始化服务按 Compose 依赖关系判断。中断、失败或尚未就绪会明确显示，已有配置和数据保留。模板安装与现有 Compose 部署也使用环境检查和服务就绪判断。

“多机管理 → 设备能力与批量任务”集中显示本机、探针、回连设备和 SSH 设备。每台 DIANCUP 设备可维护部署档案：项目目录、允许挂载的真实目录、媒体等资料库目录、PUID/PGID、时区及端口范围。硬件架构与设备路径由服务检测。只读模式会阻止设备管理 API 的写操作及助手本机命令，管理员仍可修改设备档案；SSH 工作台是独立授权的连接方式。

批量任务支持检查更新和更新指定容器，每台设备保存实际子任务编号与执行结果。停止操作会发送到原设备；网络中断后可“重新核对子任务”，只查询已经提交的任务。无法确认的结果会标为待检查，不自动重放写操作。

### 异地主机主动回连

在设备能力工作台中选择“添加回连设备”，填写名称及该设备可访问的管理端 HTTPS 地址。将生成的 Compose 保存到目标设备，把 `DOCKER_DIR` 改为宿主机真实项目目录后部署。回连设备默认监听 `127.0.0.1`，通过管理端执行操作，无需开放其管理端口。HTTP 管理端仅支持内网 IP 或 localhost，公网使用 HTTPS/WSS。

连接支持独立配对凭据、心跳、退避重连、文件流式传输及实时日志通道。删除设备会断开对应连接，重新连接不会自动重复写操作。生成的配置包含设备凭据，可在对应服务器的“安装配置”入口再次查看；设备列表、普通详情和浏览器切换上下文不包含凭据。

### AI 页面操作

模型提供商保存后，可检测连接与鉴权、文本生成、工具调用和结果回传；未提供模型列表接口的服务继续检测实际推理。轻量任务可独立选择提供商和模型，留空沿用默认设置。

Compose 编辑器的“AI 配置”会对照当前内容生成候选配置，应用前可查看结果。部署任务入口支持 Compose 与 `.env` 一并生成，并携带目标设备档案；将已有 `.env` 发给模型服务需在窗口中主动勾选。日志窗口的“AI 分析日志”会携带容器身份和当前日志打开助手，供检查后发送。导航卡片的 AI 整理提供名称、描述和已有分类建议，只补齐空白项，保留现有内容。

## 页脚与导航设置

登录导航后，从「导航管理 → 定制外观与布局」调整外观、背景和布局。外观页的「页脚」可修改名称、介绍和 GitHub 地址，或隐藏整个页脚。

登录后可右键卡片编辑内容、调整尺寸或固定到手机底栏；手机也支持长按菜单。第三方组件的凭据由服务端使用，私有分类和入口仅在登录后展示。
